# Atom 交互原子隔离设计

## 目标

每个 Atom 交互都是独立的原子闭环。一个交互的计算、Program、超时、失败、回滚或回执不得阻塞其他 Explore 或 Transform。全局只允许在最终权威世界提交的短临界区内互斥。

## 根因

`cli/lib/server.mjs` 用 `atomInteractionTail` 串行整个写交互，并让 Explore 等待该尾链。任一写交互未完成时，后续命令虽与它无关，仍全部等待。这不是“队列失活”的状态问题，而是完整交互被错误放入全局串行区的架构问题。

## 权威契约

- **独立执行**：Agent 解析、语言执行、Program 评估和候选世界计算均属于当前交互，不持有全局交互锁。
- **即时读取**：Explore 直接读取最近一个已提交世界，不等待活跃写交互。它不保证看到尚未提交的候选事实。
- **短提交区**：只有“复验基础修订 → 写准备日志 → CAS 世界 → 写提交日志”串行；长计算不得进入。
- **冲突终止**：候选世界基于旧修订时，返回 `WORLD_REVISION_CONFLICT`；不在内核盲目重放业务 Transform。
- **交互截止**：每个交互有独立期限和 `AbortSignal`。超时只终止它自己，结束为明确终态回执。
- **超时不可迟到提交**：交互终止后，其背景计算即使迟到返回，也必须在准备日志和 CAS 之前被拒绝。
- **投影解耦**：投影只在权威提交后异步运行，失败进入可恢复投影状态，不占用交互或提交临界区。
- **幂等回执**：同一 interaction id 仍只执行一次；同 id 不同请求仍拒绝。这不允许不同 id 的原子互相等待。

## 验收

1. 一个 Transform 永不返回时，后续 Explore 可在独立时限内返回最近已提交世界。
2. 一个 Transform 永不返回时，另一个不冲突 Transform 可独立提交。
3. 两个并发 Transform 基于同一修订且冲突时，最多一个提交，另一个明确冲突，不得丢写。
4. 交互超时后返回 `ATOM_INTERACTION_TIMEOUT`，候选事实永不进入权威世界。
5. 一个交互的 Program 失败、投影失败或客户端断开不改变其他交互的可用性。
6. 同 interaction id 重试共用同一终态回执，不重复执行。
