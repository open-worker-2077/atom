# Atom 运行、投影与恢复设计

## 1. 责任边界

- **负责**：定义统一交互生命周期、世界修订、中央事务、Program 调度、投影发布、局部性能、就绪、备份和恢复。
- **依赖**：世界规格定义可提交语义；Agent 规格提供授权结论；Web/CLI 消费同一回执和投影。
- **不负责**：不重新解释 Thing、Program 或 UI 行为，不把运维记录变成业务事实。
- **主要来源**：Issue #7、#20、#24、#29；交叉吸收 #31、#45 的运行故障边界。

## 2. 统一运行脊柱

### 2.1 交互生命周期

- **接收**：CLI、HTTP、Web 或 Program 请求进入同一入口模型，携带关联标识、Agent、意图和候选 revision。
- **裁定**：在不可变候选世界上完成坐标解析、授权、Graph四轴及事实不变量验证；显式Program调用按其自身运行边界生成effects。普通事实改造的后续业务触发不成为合法来源提交的前置条件。
- **提交**：通过串行中央事务检查预期 revision、幂等键和不变量，成功后只推进一次世界修订。
- **投影**：由已提交 revision 更新 Graph/Spatial 和相关索引；投影携带来源 revision，不反向改世界。
- **回执**：返回事实提交、投影进度、warnings、错误原因和可追踪关联标识，不用模糊“成功/失败”遮住边界。
- **后续运行**：来源提交成立后，按实际Transform事件及既有索引触发下一步；单独记录后续运行与效果提交结果，失败不把来源回执改成未提交，也不以关闭触发需求代替隔离。

### 2.2 中央事务

- **单一提交点**：来源Transform与后续Program effects都复用中央事务入口；各自事务的事实、锁变更和可逆记录原子裁定。复用提交点不等于把来源改造与所有后续delivery合成一个成败边界。
- **并发保护**：候选 revision 过期时稳定冲突；不得在旧世界上补写或让最后到达的旧快照覆盖新提交。
- **幂等重试**：同一操作重试复用中央回执；不得产生第二次业务提交或重复触发 Program。
- **提交证明**：事务历史记录“未提交、已提交、投影等待发布/已发布”的可解释边界，辅助日志不是唯一证明。

### 2.3 Program 调度

- **时间边界**：Program 具有明确超时、取消和失败隔离；运行时停止不能无限等待隐藏任务。
- **并发边界**：只调度精确命中的 Program/订阅，不扫描和执行无关世界 Program。
- **修订绑定**：后续delivery可追溯来源提交及其事件；每次Program运行的判定与effects绑定自身读取的revision，提交冲突后重新读取而非盲目复用结果。
- **失败隔离**：Program异常不发布该次运行尚未提交的effects；此前已提交的来源事实保持成立。已提交后的业务触发、投影或诊断失败必须分别报告，不伪装成来源回滚成功。

### 2.4 原子化与生命周期归属（2026-09-05用户定论）

- **独立裁定**：来源改造、随后Program运行、投影恢复是相互关联的不同作用，各自拥有输入、完成证据、错误和恢复边界；关联标识不把它们合成一个成败或取消域。
- **来源终态**：中央回执证明来源已提交后，该结果不可由后续运行、展示恢复、通知或请求超时改成未提交。后续是否触发继续按既有有效规格判定，不因分离而取消。
- **运行终态**：后续effects已提交，或运行已明确完成且没有事实effects，均可形成completed；已经确定的业务错误形成failed。两种终态都不依赖投影收尾，须及时持久记录并供同一关联查询，不能因没有child receipt就推定运行尚未完成。
- **取消归属**：超时/取消必须标明其实际作用对象和发生阶段，只能中断尚在执行的对应作用。投影阶段的超时、迟到AbortSignal或HTTP等待结束，不得把已经完成的业务结果降为pending；真正中断且无确认结果的后续尝试才进入恢复。
- **投影恢复**：投影从已提交事实重建，有自己的pending/失败/恢复进度；其延迟和错误以投影状态及诊断报告，不阻塞业务终态确认，也不借补投影重跑Program。

## 3. 就绪与投影

### 3.1 启动就绪

- **健康区分**：进程存活和 HTTP health 只说明服务可响应；命令就绪还要求世界加载、必要索引、Agent/Program registry 与提交入口可用。
- **公开状态**：启动期间返回明确 loading/not-ready 和阶段原因，不先报 `ok=true` 再让首条 Agent 命令失败。
- **首命令门**：正式 ready 前执行写入或 Program 请求必须安全等待或稳定拒绝，不进入半初始化运行路径。
- **冷启动一致**：索引和 registry 从当前世界重建；不存在必须靠旧侧车才能成功的隐藏前置条件。
- **全局热态**：4784 对外监听前必须完成一次权威世界与 Graph/Spatial 投影读取、校验、revision 计算，以及 exact path、slot/strut、Agent、锁、Program、trigger/read dependency、Shortcut、后代重写和局部查询目录准备；准备结果按进程驻留，不得在首个 CLI/Web 请求中丢弃后重建。
- **真实首入**：ready 不以 HTTP health 单独成立；同一启动验收必须证明首个公开 Agent 命令、exact 回读和 Web 局部 state 请求均直接消费已驻留热态，且初始私密恢复备份已经完成。

### 3.2 投影合同

- **可重建**：Graph 与 Spatial 是已提交世界的读模型；损坏、缺失或落后时可从来源 revision 重建。
- **修订标记**：每个投影结果声明 source revision；消费者拒绝较旧响应覆盖当前场景。
- **异步边界**：世界提交成功后投影可处于 pending；pending 不是提交失败，回执必须让调用方知道事实已提交。
- **失败补偿**：投影发布失败记录诊断并重试/重建，不能撤销已经成功的世界事务或把世界改回旧快照。
- **局部发布**：正常交互只更新受影响闭包；完整重建用于冷启动、损坏恢复或明确的维护操作。

## 4. 局部性与持久结果

### 4.1 影响闭包

- **启动准备**：启动期恰好完成一次必要的全局事实与投影准备并保留不可变热快照，为交互期精确定位服务；请求期不得重新读盘、重新清洗或重新构造完整世界/投影。
- **交互局部**：一次 Transform 只读取目标路径、授权路径、相关 strut/Program、引用和投影闭包。
- **反向索引**：slot、strut、Shortcut、Program 触发与权限路径均维护可按 revision 校验的反向入口。
- **有界回退**：索引缺失或陈旧时，只对能证明与目标相关的范围回退读取；必须全量重建时转为明确维护/恢复路径。
- **投影所有权**：进程运行期间 Spatial Store 拥有当前 revision 的驻留投影快照；磁盘文件只承担启动恢复与原子持久化，局部查询不得把磁盘文件当作逐请求数据库。写入只有在持久化成功后才能替换驻留快照。

### 4.2 性能要求

- **禁止放大**：局部 Transform 不得在热路径全世界扫描、复制完整快照、重建所有投影或唤醒无关 Program。
- **测量对象**：同时记录世界规模、受影响对象数、读取/写入数、Program 数、投影范围和端到端时延。
- **门槛绑定**：性能证据绑定代码版本、数据规模和执行入口；旧版本的“低于 5 秒”等结论不能自动继承。
- **先证因果**：性能退化先由系统化调试定位放大环节，再做最小修复；不以调高超时遮蔽全局工作。

### 4.3 Web 持久成功

- **一次操作**：Web 移动、编辑或删除只提交一次明确意图，不由定时全量保存覆盖权威世界。
- **成功回读**：提交回执后，从不低于该 revision 的权威 state 回读目标，确认身份、坐标、内容和关系。
- **刷新保持**：F5/重启后由世界事实重建出相同业务结果；仅页面内模型变化不构成交付。
- **视图独立**：投影重建保留 Web 规格定义的相机、选择和展开事实，除非用户同时发出视图意图。

## 5. 维护、备份与恢复

### 5.1 授权维护迁移

- **显式入口**：ABI、Agent 格式或索引重建等维护迁移使用独立、受授权、可审计的维护命令，不伪装成普通用户 Transform。
- **前置快照**：执行前生成可核验的私密数据备份、对象映射和候选 revision；敏感正文不进入公开仓库。
- **原子批次**：能原子完成的转换一次提交；无法无损转换时停止并报告精确对象，不留下新旧规则混用。
- **当前复验**：迁移后冷启动、索引重建、公共入口和真实用户链按新合同复验。

### 5.2 运行恢复

- **事实优先**：恢复首先确定中央事务是否提交，再处理投影、索引、服务和辅助镜像，避免重复写入。
- **私密备份**：权威写入触发仓库外备份；备份包含恢复所需事实和校验信息，不公开业务数据。
- **代码回退**：部署前记录 Git 基线、构建标识与配置；代码回退不自动回滚已提交的新业务事实。
- **合同重验**：恢复的 Program、Agent 和关系按当前版本合同重新登记/投影；历史备份不能复活已退役权限或运行语义。

### 5.3 辅助记录失败

- **中央回执**：事务历史是提交判定的首要运行证据。
- **镜像降级**：审计 JSONL、诊断导出或报告写入失败时，已提交操作返回成功加 warning，并允许后续补写。
- **未知状态**：只有无法读取中央回执且无法证明提交与否时才报告未知；恢复流程先查关联标识，不盲目重试。
- **告警可行动**：错误包含关联标识、候选/实际 revision、提交边界和投影状态，避免依赖长日志猜测。

## 6. 验收与追溯

### 6.1 必要验收场景

- **启动矩阵**：全新启动、旧侧车缺失、索引损坏、Program registry 重建和首条命令同时验证 health 与 ready 区别。
- **首请求工作量**：在不少于 10,000 个空间实体的验收投影中，Store 启动后首个 health、根域 state 和深层局部 state 请求均不得再次读取或规范化完整投影；每项本机端到端延迟低于 1 秒。
- **事务矩阵**：成功、预期 revision 冲突、幂等重试、提交前失败、提交后镜像失败与投影失败均验证事实守恒。
- **局部性能**：不同世界规模下固定小闭包的读取、Program、写入和投影工作量不随全世界线性放大。
- **持久 Web**：移动/编辑的提交、权威回显、F5 和服务重启保持同一业务结果，不出现旧响应覆盖。
- **恢复演练**：代码回退、投影重建、私密数据恢复和当前合同复验可按记录执行。

### 6.2 证据重绑定

- **OpenSpec 未闭项**：`eliminate-global-runtime-amplification`、`enable-authorized-maintenance-migrations` 等历史清单存在未勾项，不能靠后续 PR 描述自动补齐。
- **当前版本**：后续计划先把旧验收意图转成当前 `main` 的聚焦测试/诊断，再裁定具体差距。
- **历史轨迹**：PR #16、#21、#22、#30、#33、#34、#36、#37、#40 用于定位实现和回归来源，不直接授予完成结论。
- **跨域关系**：#31 的 CLI 入口需同时满足 Agent 格式/权限；#45 的可逆记录需同时满足世界软删除合同。
