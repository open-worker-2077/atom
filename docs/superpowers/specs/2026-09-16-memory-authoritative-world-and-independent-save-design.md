# 运行期内存唯一事实与独立保存设计

## 用户定论与替代边界

- 运行期只有一个事实所有者：进程驻留的世界内存中转站。CLI、Web、Program 的合法交互在同一入口裁定后，原子地更新内存版本；下一次读取立即观察该版本，不等待磁盘保存、投影或后续 Program。
- 保存是另一环节：交互使世界变脏并触发适度频率的周期性保存；保存独立执行，不能阻塞内存事实的读写，也不能以低频、大量全量重复工作掩盖自身低效。
- 磁盘是重启恢复点，不是运行期与内存竞争的第二事实源。保存完成只推进已保存版本水位，旧保存结果不得覆盖更新的内存事实。
- 本规格替代既有《Atom 局部原子提交设计》中“日志 fsync 后才切换内存并可读”的交互时序，以及《Atom 运行、投影与恢复设计》中“持久化成功后才能替换驻留快照”的时序。既有授权、局部影响闭包、单次 Transform 原子性、幂等、Program 独立终态和可逆语义继续有效；相关旧规格须标注被替代条款，避免双重权威。

## 系统本体与合同

| 能力 | 拥有的事实或状态 | 对外合同 | 失败边界 |
|---|---|---|---|
| 内存世界 | 当前世界版本、四轴事实、授权和局部索引 | 单一原子交互入口；同一进程后续读必见已接受写；返回内存版本与变脏状态 | 非法意图不改变版本；并发冲突不静默覆盖 |
| 保存器 | 待保存版本、已保存水位、一次保存任务 | 从不可变版本取稳定快照，按版本顺序独立持久化；短静默窗口合并触发并设置最长未保存时限 | 重试与可见失败，不修改内存世界或倒退水位 |
| 恢复器 | 最新经校验的完整保存点 | 冷启动仅在加载并校验保存点及必要索引后对外 ready | 损坏保存点不伪装成功；回退到前一个有效保存点并报告 |
| 派生消费者 | Graph、Spatial、Agent/Program 索引和 Web 场景 | 消费标记来源内存版本的事实；旧版本不能覆盖新版本 | 投影失败不回滚已接受内存事实 |

运行期内存事实与持久恢复点允许短暂版本差，公开回执必须区分 `acceptedRevision` 与 `savedRevision`，不能把“内存已生效”称作“已安全保存”。程序或机器在保存前退出，尚未保存的内存版本可能丢失；这是该模型的明确恢复语义，不以隐藏的同步 fsync 偷换。正常停机应请求保存并有界等待，异常退出按最后完整保存点恢复。

## 运行与性能规律

1. 交互只在局部闭包内解析、授权、校验与更新；内存版本原子前进，读取从同一版本取得事实和兼容清单。保存 I/O、全量哈希、压实和重建不得处于交互的等待链或全局读锁中。
2. 保存调度采用交互后短静默窗口与最长脏版本年龄的双界限：连续编辑可合并，持续编辑也必须周期保存；无修改不重复保存。窗口与上限由实测负载确定并可配置，不在规格中臆定秒数。
3. 同一世界至多一个有效保存写者。写者捕获不可变版本；若内存继续前进，完成旧版本后推进水位并继续调度最新脏版本，不以旧文件回填内存。保存过程中读取和新的交互仍可继续。
4. 保存本身必须测量快照准备、增量记录、序列化、I/O、校验、原子替换和滞后；优先复用现有局部补丁与压实能力，但不得让 12k 级归档历史在每个保存周期重复扫描或重写。背压、重试与磁盘空间错误必须可观察，不能无限积压或悄悄丢弃。
5. Program 来源与后续 effects 各有独立的内存原子边界；授权及锁绑定其读取的内存版本。通知、投影和保存不得把已接受来源改造成未接受，或反向修改已接受事实。

## 迁移与验收

- 先在隔离的真实规模副本建立 RED：普通写后立即 Explore/Web 回读；人为阻塞保存时连续读写仍完成；连续写只推进版本且旧保存不能覆盖新值；重启只恢复已保存水位。
