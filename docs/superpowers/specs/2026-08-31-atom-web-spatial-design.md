# Atom Web 与空间体验设计

## 1. 责任边界

- **负责**：定义权威路径加载、场景回显、数据编辑、层级导航、Shortcut、复合 strut 几何、映射参数和移动端入口。
- **依赖**：世界规格提供身份与关系；运行规格提供提交、revision 和投影；Agent 规格提供访问结果。
- **视图所有权**：相机、焦点、选择、展开状态、视图模式和显式布局覆盖属于空间体验，不写回业务世界。
- **主要来源**：Issue #12、#17、#23、#41、#43、#46、#47；交叉验证 #24、#62。

## 2. 权威路径加载

### 2.1 状态模型

- **加载中**：进入新路径、返回父层或等待较新 revision 时，保留可理解的当前上下文并明确显示 loading。
- **已就绪**：只有权威 state 明确返回该路径在目标 revision 的结果后，才允许把节点列表解释为真实空或非空。
- **失败**：网络、权限、路径失效或投影错误显示具体原因，并冻结会破坏事实的编辑动作。
- **请求竞争**：每次导航带路径/请求标识；迟到的旧响应不得覆盖用户已进入的新路径。

### 2.2 首次进入与空域

- **不伪装为空**：未知/加载状态不得渲染成可编辑空域，避免用户把未加载节点当作不存在并误删。
- **即时入口**：应用外壳可先显示，但域内容等待权威状态；不能依赖约 10 秒后的偶然轮询才出现。
- **缓存使用**：可先展示带 revision 的最近场景作为“陈旧预览”，但必须标明并禁止其覆盖更高 revision。
- **恢复策略**：请求失败可重试当前路径；不自动跳往相邻同名域或顶层假默认域。

## 3. 编辑与场景连续

### 3.1 编辑链

- **明确意图**：创建、改名、移动、关系、删除各自产生一次明确数据意图，经统一运行脊柱提交。
- **权威成功**：UI 只在中央回执确认提交后标记成功，再用不低于提交 revision 的 state 对账。
- **禁止覆盖**：定时保存、旧本地快照或迟到投影不得覆盖刚提交的事实。
- **持久结果**：F5、域进出和服务重启后，目标身份、坐标、内容与关系保持一致。
- **已修—Transform即时对账**：2026-09-02真实4784再现Web改名已显示成功，但退出再进入同一域仍显示旧事实，约两分钟后才自动一致；2026-09-03再次确认CLI已完成并回读`瞻判／排针`改名与父节点正文后，已打开的Web局部视图仍显示`瞻权／判针`。根因之一是EventSource短暂断开期间的revision通知会丢失，重连又不核对当前revision。现已要求重连立即拉取当前路径与已展开路径，并在同一revision齐备后一次导入场景；首次连接不增加重复拉取，仍不轮询或刷新全世界。持续连接提交、断线漏事件重连、展开路径原子导入和入口内容哈希均有自动化验收。

### 3.2 保持视图

- **默认守恒**：数据编辑后的投影重建保留相机、焦点、选择、展开分支和当前视图模式。
- **显式例外**：只有目标被删除、变得不可见或用户同时发出导航意图时，才按可解释规则选择新锚点。
- **身份对齐**：选择与展开按稳定 Thing id/关系 id 对齐，不依赖会随改名或移动改变的显示路径。
- **已修—内部身份隔离**：普通名称、镜面与悬浮详情不再把 `@slot-role-<内部ID>`、`@slot-revision-*` 等派生身份拼进用户语义名称；稳定 ID 仍保留在权威结构化身份层。修复在投影边界按正式公开类型过滤，不做显示字符串截断；投影专项`13/13 PASS`，真实4784重启后投影为`published`且用户可见`knowledge.json`中内部标识命中为0。
- **真实验收**：必须比较浏览器最终屏幕坐标、节点半径、选中对象和相机，而非只检查内部模型变量。
- **待修—CLI 后视图紊乱**：CLI 引起的节点增删改移可触发对应数据与局部投影更新，但不得重置或错配相机、焦点、展开层级、节点尺度及显式布局覆盖；以同一路径操作前后的最终屏幕结构连续性验收。

## 4. 导航与关系呈现

### 4.1 A 向内剖开与沉浸（已定方向，待实施）

- **唯一结构视图**：本体包含关系只使用 A 的内嵌结构表达；S、D 不再作为现行模式。既有实现退出运行路径后进入可恢复封存，不直接清除历史。
- **普通剖开**：右键单击当前团，只向内剖开其团内 Slot 结构；团外上下文继续可见。不得称为“向外展开”，避免回到 S／D 的外部铺展语义。
- **沉浸剖开**：右键双击当前团，仍沿 A 的 Slot 结构向内剖开，但把该团设为当前可见边界，隐藏团外节点、边与上级背景。沉浸是 A 的可见范围状态，不再作为独立 F 视图模式。
- **同一加载合同**：普通剖开、沉浸剖开和返回父层调用同一权威路径状态接口；快速连续钻取时按请求身份和 revision 排序。
- **待定交互**：A 键是否保留为显式恢复普通剖开状态，须在实施计划前完成最后一次交互裁定；本条不阻塞其他既定缺陷处理。

### 4.2 Shortcut 激活

- **目标跳转**：激活 Shortcut 后解析 linked stable id，并导航到目标所在权威路径、选中目标。
- **权限重判**：目标访问按真实 slot 路径重新授权；Shortcut 不借出权限。
- **失败保持**：目标缺失、越权或加载失败时留在当前有效场景并显示原因。
- **返回一致**：从目标返回使用相同路径历史和加载合同，不把 Shortcut 自身伪装成目标副本。
- **已完成—Shortcut 深层激活**：普通、未访问深层、A 模式、坏链保持和渐进远端路线均通过真实 Chromium；激活先解析 linked target，再按权威路线进入并选中目标，不进入 Shortcut 自身的本地空域。
- **已完成—Shortcut 语义编辑**：人工与 Agent 使用唯一语义路径修改 Shortcut；公开 Transform 为 `{"thing.lnk.EXACT_TARGET":"EXACT_SHORTCUT"}`，Atom 负责消歧并保持 stable identity，多个候选时拒绝猜测。Web 只呈现名称和目标路径，不把合同 JSON 或内部 ID 当正文暴露；改名与改向可在同一原子 Transform 中完成。

### 4.3 复合 Strut

- **真实 H**：显式枢纽 H 作为真实可命中、可选择节点呈现，不被共享线干隐藏。
- **两段身份**：N→H fan-in 与 H→M fan-out 保留独立 clause identity、方向和标签。
- **50% 几何**：fan-in 在标准化 50% 汇合，fan-out 在标准化 50% 分流，形成连续但不合并的线干。
- **局部重建**：只重建当前可见关系团；进入、返回和重绘后关系身份稳定，不写 `atom.json`。

## 5. 输入映射与移动端

### 5.1 A 映射参数

- **A 缩小**：只改变子层节点最终可见半径/缩放，不改变父域或同层间隔。
- **即时局部**：滑轮变化立即重算当前可见场景，不触发世界提交、全域事实刷新或无关域投影。
- **屏幕证据**：验收比较实际渲染后的屏幕边缘间距与半径；内部 `clusterGeometry` 变化不能作为替代。

### 5.2 输入说明

- **设备区分**：控制面板区分鼠标动作、滚轮/触控动作和键盘按键，不用同一图标让用户猜测。
- **模式收束**：完成上述改构后，帮助与设置只呈现 A 向内剖开及其普通／沉浸动作，不再把 S、D、F 显示成并列模式；实施前仍须按当前真实输入映射说明，禁止文档先于代码制造假状态。
- **窄屏可达**：390px 等窄视口下主要控制可见、可触达，不被面板遮挡或挤出视口。
- **语义不分叉**：移动端适配不复制业务逻辑，仍通过相同意图、权限、提交和加载链。
- **已定设计—可编程点击次数**：输入层把每次物理点击作为一个原子事件，并在同一稳定目标、同一按键和有效间隔内形成不设上限的累计次数；Program 声明自己订阅的精确次数。三点击运行只是`count:3`的具体用例，Web 不得把“三点击=运行”写死，也不能破坏未命中 Program 时单击选择和双击进入的既有语义。
- **已修—双击命中**：A 模式展开后，外层 cluster shell 与可见内层节点重叠时，以指针实际落入的最具体内层节点作为稳定点击目标；双击不得因外层已选中优先级而激活上级节点，并以最终`activate`目标身份验收。
- **已修—Strut 贴边**：普通视图与 ASDF 共用 Strut 语义绘制层；首末端按最终`screen.radius`裁剪到可见节点边界，实际绘制端点同步进入验证几何，fan-in/fan-out 的 50% junction、条款身份与事实保持不变。

### 5.3 可编程点击次数

- **序列身份**：一次点击序列由稳定 Thing id、指针按键和相邻点击时间共同界定；显示路径、标签或临时绘制对象不能充当身份。
- **累计规则**：每次物理点击立即形成一次规范化 Transform `thing$click`动作，动作信封依次携带`count:1、2、3……`；实现不得设置最大次数。目标或按键变化、相邻点击超过既有手势间隔时，新序列从`1`开始。
- **声明合同**：点击次数不是独立 `trigger("click")`。目标相关 Strut 的内嵌 `if` Program从统一 Transform action envelope 读取 exact Thing、按钮与累计次数，按自身条件 strict-bool 判定；`$click`与未来注册动作共用同一入口。
- **运行边界**：浏览器只提交稳定命中的 exact Thing 与注册 `$click`动作参数，不提交 Program 名称或运行权限；4784 通过统一 Transform 解析、Graph 路径、锁鉴权与 Strut clause 索引处理。CLI 对同一 Thing 的同构 Transform 必须产生同一判定上下文。
- **既有交互**：没有 Strut 条件命中 strict true 时，继续执行当前输入映射；判定或后项 Program 失败不得吞掉既有选择、进入或错误提示，也不得把后续次数错误归入已经重置的序列。
- **验收矩阵**：以隔离测试世界证明单目标连续`1→2→3→4`、目标切换重置、超时重置、Strut 精确次数条件、无 Strut 保持旧行为、越权不执行、重复动作不重复投递，并用 CLI 与真实浏览器证明第三次 `$click`可使目标 Strut strict true。另注册非 click 测试动作，证明 Web/Strut 主干没有 click 特判。

### 5.4 主入口恢复

- **原标签页恢复**：启动被中断、后台 worker 重启或部分资源失败后，原标签页可恢复连接和当前路径。
- **关键资源优先**：可选字体和非关键资源不得阻塞应用 ready；失败时使用本地/系统回退样式。
- **状态可见**：恢复中显示阶段，不反复刷新为空页面或要求用户新开标签页。
- **无隐藏任务阻塞**：运行停止/重启不被非关键 worker 或资源任务无限拖住。

## 6. 错误与验收

### 6.1 错误合同

- **加载错误**：显示路径、请求阶段和可重试动作；未知状态下禁编辑。
- **提交错误**：回滚乐观视觉变化或用权威 state 对账，不保留“看似成功、刷新消失”的结果。
- **投影延迟**：显示事实已提交、投影待发布，不把 pending 误报为写入失败。
- **渲染错误**：局部关系或布局失败不得破坏当前世界事实；允许重建场景并保留有效视图锚点。

### 6.2 真实浏览器旅程

- **首入旅程**：冷启动 → 首次进入普通域 → loading 可见 → 节点出现；真实空域与加载态可区分。
- **编辑旅程**：创建/移动/关系/删除 → 一次提交 → 权威回显 → 相机/选择保持 → F5/重启仍在。
- **导航旅程**：普通与 F 的父→子→父、快速连续导航、Shortcut 跨域和失败返回均按同一合同。
- **关系旅程**：点击 H、分别命中两段 clause、验证 50% 汇流/分流、返回全域后身份仍在。
- **设备旅程**：桌面与 390px 视口验证入口恢复、控制提示、S/A 最终屏幕效果和无业务写入。
