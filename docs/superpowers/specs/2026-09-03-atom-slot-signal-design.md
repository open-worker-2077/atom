# Atom Slot 相邻层级信号设计

## 1. 目标与边界

- **能力目标**：沿既有 Slot 父子层级传导临时业务信号，使接收节点自己的 Program 可按来源与标签决定是否运行。
- **关系边界**：只提供当前节点到直接父节点或直接子节点的表达，不新增第五种 Graph 关系，不提供任意目标、路径、跨层或同级参数。
- **事实边界**：信号本身不修改 Situation、Slot 或其他世界事实；接收 Program 若产生 Transform，仍进入现有鉴权与中央原子事务。
- **续传边界**：信号不自动续传。中间节点若需继续向上或向下传导，必须由自身 Program 再次显式调用 `slot(...)`。

## 2. 公开 Program 合同

### 2.1 发送

```python
slot({"to":"up","labels":["状态上报"]})
slot({"to":"down","labels":["受伤通告","紧急"]})
```

- **`to:"up"`**：发送给唯一直接父节点。
- **`to:"down"`**：广播给全部直接子节点。
- **标签**：由业务定义；同一次调用中的标签按集合匹配，不承载隐式目标坐标。

### 2.2 接收与触发

```python
def receive():
    notice = signal()

trigger("slot", {
    "from":"down",
    "labels":["状态上报"],
    "match":"all"
}, receive)
```

- **本节点负责**：只检查接收节点自己的 Program；只有显式声明 `trigger("slot", ...)` 且匹配的 Program 才运行。
- **来源视角**：`from:"up"`表示信号来自父节点，`from:"down"`表示信号来自子节点。
- **默认匹配**：`match:"all"`要求信号包含 Program 声明的全部标签。
- **精确匹配**：`match:"exact"`要求两侧标签集合完全相同。
- **暂不提供**：`overlap`、被包含或模糊匹配，避免扩大误触发面。

### 2.3 当前信号

```python
notice = signal()
# {"from":"up|down","labels":["业务标签"]}
```

- **调用域**：`signal()`是标准 Program 内建函数，读取当前 invocation-local 信号上下文；不是进程级可变全局，也不是用户自定义函数名。
- **隔离性**：并发 Program 各自读取本次调用的信号，不能串入其他节点或其他执行的上下文。
- **越界调用**：在 Slot 信号触发之外调用必须明确报错。
- **最小公开载荷**：首版只公开 `from`与`labels`；内部事件身份、修订和防重元数据不得混入业务合同。

## 3. 节点与 Program 归属

- **单点归属**：每个节点只管理自身 Program；发送方不能指定接收节点运行哪个 Program。
- **自主触发**：接收节点以自身 `trigger("slot", ...)`声明决定是否响应；未声明或标签不匹配即不运行。
- **向下广播**：父节点的 `to:"down"`只投递到 Graph 已确定的直接子节点；各子节点独立匹配自己的 Program。

## 4. 调度与事务

- **瞬时信号**：Slot 信号属于运行事件，不形成世界事实写入。
- **防重内核**：运行时可使用事件身份、候选修订和消费记录保证同一投递不重复执行，但这些字段不进入首版业务 API。
- **失败守恒**：匹配、调度或接收 Program 失败时，不得留下半份事实副作用；Program effects 继续服从中央事务的原子提交。
- **权限守恒**：信号到达不等于授予写权限；接收 Program 的作用范围仍按自身 Agent 窗口、锁和 Transform 权限裁定。

## 5. Strut 边界纠正

- **Clause 决定后项**：Strut 的 Graph 结构确定 true 应交付给哪些后项；复合推支线仍由真实 clause 关系确定汇流与分流。
- **Program 只作判定**：Strut `if`内嵌 Program只判断前项是否成立并返回严格布尔值，不声明或选择后项。
- **后项自主响应**：true 到达后，由后项自身 Program 是否声明 `trigger("strut", ...)`决定是否运行。
- **`nodes`属设计赘余**：现有 `trigger("strut", {"nodes":[...]}, ...)`把 Graph 已确定的接收方再次交给 Program声明，违反上述归属。Slot 首版不得复制该字段。
- **迁移分轨**：现有共享槽模 Program仍依赖相对 `nodes`，其清除需单独建立一次性迁移与回归，不在 Slot 首版中暗中兼容两套合同。

## 6. 验收

- **向上成功**：子节点 `slot({"to":"up",...})`只唤醒直接父节点中匹配的自身 Program。
- **向下成功**：父节点 `slot({"to":"down",...})`广播到全部直接子节点，只有各自匹配 Program运行。
- **标签隔离**：`all`与`exact`按合同工作；未匹配标签不执行，多个标签互不串扰。
- **层级限制**：公开 API无法表达任意目标、跨层或同级发送；中间层不自动续传。
- **上下文隔离**：并发信号的 `signal()`值不串扰，触发域外调用明确失败。
- **事实守恒**：仅发送信号不改变世界修订；接收 effects 成功时原子提交，失败时无半份副作用。

## 7. 已核验的开发前风险

### 7.1 P0：4784 命令端队列失活

- **当前证据**：`/__spatial/api/health`可快速返回，但最简单的 `explore 🧊manage`超过 30 秒无输出，症状在当前版本可复现。
- **结构原因**：服务端以单一 `atomInteractionTail`串行化写入，并让 Explore等待该写入尾部；某次写入不收敛时，后续命令全部被阻塞，而 health 绕过该队列所以仍显示正常。
- **预算缺口**：Program Scheduler有单轮 10 秒预算，但 reconciliation 最多八轮，交互队列外层没有已证实的总截止时间、取消与终态诊断。
- **证据边界**：已经确认“队列被未完成写入占住”和“缺少总交互边界”；尚未定位是哪一个具体 Program或循环使该次写入不收敛。
- **修复要求**：先以测试复现“未收敛写入阻塞后续 Explore”，再增加总交互预算、取消/失败收口、原子回滚、队列释放和终态诊断；重启服务不构成修复。

### 7.2 Strut context 边界纠偏

- **已有结构**：运行时已经公开 `antecedents[].{path,thing,situation}`、`consequents[]`和可选 `transform`；规范化动作信封提供 `targetPath/action/parameter/payload/source`。
- **业务职责**：业务 Program依据复合前项当前事实与本次动作信封决定是否返回 strict true；调用方负责决定是否发起 Transform。内核不替业务比较旧值、新值，也不以“值是否变化”裁定该动作应否发生。
- **当前结论**：撤回“补充旧值、新值与状态跃迁合同”的待开发项。后续只在具体业务确有无法由当前事实与动作信封表达的证据时，重新形成独立规格。

### 7.3 已撤回项

- **原生幂等**：不新增 `once_per_revision`；是否发起 Transform及 Strut 条件是否为 true 均由业务侧按当前事实与动作语义裁定。
- **本地节点清理**：接受软停用并保留槽体来源，不作为当前 Atom缺陷。
- **纵向传导**：由本规格的 Slot信号直接进入开发，不再重复登记为独立 `climb`需求。
