# Atom ESG 阶段推进与执行迁窗设计

## 1. 目标与边界

- **用户结果**：ESG 计划按既有 Strut 链逐阶段推进；前置阶段完成后，后续阶段解除业务锁、进入可编辑的进行中状态。
- **状态词汇**：`🏃‍♀️` 表示进行中且允许编辑，`⌛️🔒` 表示等待且禁止普通编辑，`✅` 表示由业务执行人员确认完成。
- **当前范围**：先保证状态推进和业务锁闭环，再实现已完成槽例的执行 Agent 自动迁窗；Web 交互 Bug 由 Web 空间规格独立约束。
- **非目标**：不把某个真实 ESG 节点伪造成已完成来测试，不直接修改 backing JSON，不为本功能增加第二套权限或状态引擎。

## 2. 阶段关系

- **第一段**：`原表守恒` 完成后，`活动建模` 从等待锁定转为进行中。
- **第二段**：`活动建模` 完成后，`执行落位`、`复盘改进/完成映射`和`复盘改进/建议映射`转为进行中。
- **第三段**：`完成映射`与`建议映射`均完成后，`复盘改进/迭代打算`转为进行中。
- **第四段**：`执行落位`、`完成映射`与`迭代打算`均完成后，`总装成件`转为进行中。
- **复盘收口**：`完成映射`、`建议映射`与`迭代打算`均完成后，`复盘改进`标记为完成。

## 3. 权限与锁

- **标签匹配层**：业务锁和负责解除该锁的控制 Agent 均使用精确标签`总控`；普通 Agent 不因处于相邻节点而继承该标签。
- **管辖层**：连续`^`只表示 Agent 管辖等级；上级 Agent 可操作自身窗口下级，下级 Agent 不得越权操作上级或兄弟窗口。
- **三类锁**：固定 Agent 窗口锁、槽体结构锁和业务 Program 锁保持独立；本功能只创建第三类锁，不能削弱前两类锁。
- **总控位置**：`ESG计划总控Agent`是五个阶段的上级窗口，使解锁与改名属于上级向下操作；它不通过同级路径或特殊维护入口绕过固定窗口锁。
- **执行身份**：由 Transform 触发的 Agent Program 使用自身声明的窗口、标签和函数授权；普通 Program 不继承其上级 Agent 的业务标签。

## 4. 状态推进事务

- **完成输入**：业务执行人员把当前进行中节点的名称前缀改为`✅`，该 Transform 是推进触发事实。
- **解锁顺序**：总控先使目标业务锁声明失效，再把目标节点从`⌛️🔒`改为`🏃‍♀️`；两项由同一次 Program 运行登记并统一提交。
- **引用守恒**：阶段改名必须统一重写 Strut 端点、Program 字面量路径和触发反向索引；内核维护已授权引用不应被目标业务锁反向阻断。
- **失败边界**：标签不足、窗口越权、路径歧义、Program 校验失败或事务冲突时整次推进不产生半完成状态。
- **真实数据保护**：自动化测试在隔离世界完成全链演练；真实世界只配置初态并以无副作用拒绝测试验证锁，不代替用户确认业务完成。

## 5. 自动迁窗

- **触发条件**：当前槽例已经由业务事实标记完成，并且下一槽例已经解除业务锁、成为可编辑的进行中节点。
- **迁移对象**：迁移当前负责该槽例的执行 Agent 窗口，不迁移总控 Agent、阶段事实或历史已完成内容。
- **授权方式**：跨兄弟槽例必须使用 Atom 官方`jump_authorize()`与`jump()`合同；上级总控签发一次性授权，执行 Agent 消费授权后迁入下一槽例。
- **提交顺序**：完成事实、下一阶段解锁与迁窗必须有明确顺序；迁窗失败时已提交的业务完成事实不得被伪装回未完成，执行 Agent 保持原位并暴露可重试错误。
- **多后项边界**：一个阶段同时开放多个后项时，只有已声明的执行分派规则可以决定目标；没有唯一目标时停止迁窗并保留全部已解锁节点，不按数组顺序猜测。

## 6. 验收

- **正向链条**：隔离世界逐项完成所有阶段，实际名称、锁状态和 Strut 关系按第二节变化。
- **反向保护**：普通 Agent 直接修改任一等待节点稳定返回`GRAPH_LOCK_DENIED`；普通 Program 不能借用`总控`标签。
- **冷启动**：4784 重启后从 Agent Program 与 literal-path lock 声明重建同一状态，不依赖 Session 记忆或侧车锁快照。
- **真实入口**：公共 Atom CLI 回读真实 ESG 初态为`🏃‍♀️原表守恒`可编辑、后续`⌛️🔒`节点锁定；真实业务节点不因验收被标记完成。
- **迁窗结果**：在槽例级测试中，完成当前槽例后执行 Agent 只迁入唯一已授权的下一槽例；授权缺失、目标锁定或目标不唯一时保持原位。
