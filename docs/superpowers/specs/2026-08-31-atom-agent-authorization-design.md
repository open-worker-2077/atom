# Atom Agent 与授权设计

## 1. 责任边界

- **负责**：定义 Agent 注册身份、授权标签、函数作用域、窗口、跳转、自锁、重配置和旧格式迁移。
- **依赖**：世界规格提供 slot 与 Program 事实；运行规格提供修订、事务和派生缓存；CLI/Web 只调用同一裁定。
- **不负责**：不把 Session、侧车文件、缓存或当前 UI 选择变成权限权威。
- **主要来源**：Issue #2、#13、#14、#31、#52，以及历史 `retire-legacy-agent-format` 合同；当前退役状态见§2.3。

## 2. Agent 身份

### 2.1 唯一注册格式

- **合法载体**：Agent 不是 Key 类型或标签；合法载体只有 `thing@program`，Agent 能力并入该 Thing 的 Program。
- **唯一声明**：Program 的 Situation 中恰有一个可静态识别的字面量 `agent({...})`；零个、多个或动态拼装均稳定拒绝。
- **唯一权威**：Agent 的身份、钥匙标签、函数作用域和窗口约束来自这个 Program 世界事实，不来自 Key 上的 `@agent`、Session 记忆或侧车注册表。
- **退役格式**：`thing@agent`、`thing@program@agent` 以及任何 Key 中的 `@agent` 均无效；公共解析、Help、CLI 和写入入口返回稳定的 retired-format 错误。

### 2.2 Program 派发 Agent

- **Program 能力**：Agent 的构造、上下文生成、派发和结果回收进入 Program 的正常能力边界，不建立 Agent 专用执行旁路。
- **统一接口**：Agent 派发复用 Program 的寻址、组合、授权、修订、超时、事务和回执机制；Program 能调用的更大工程组件沿同一扩展点演进。
- **声明与执行**：`agent({...})` 声明 Agent 配置，Program 运行时负责按该配置形成受控 Agent 执行；Key 只标识 Program Thing。
- **失败边界**：声明非法、派发失败、超时或返回异常均由 Program 运行合同处理，不产生半注册 Agent、旁路权限或孤立 Session。
- **生态约束**：不得以“Agent 特例”绕过 Program；若 Program 不能稳定派发 Agent，则视为 Program 组合能力缺口并在 Program 内修复。

### 2.3 当前实现差距

- **代码现状**：旧`thing@agent`已从活跃解析、CLI、冷启动和公共合同退役；现存`@agent`命中只允许出现在迁移／拒绝测试与历史材料。完成提交链以`df5c9e1`至`5e6ef7a`及后续回归`d5e1bb6`、`57230c0`为证。
- **迁移结果**：活跃旧 Agent 原地升级为带合法 `agent({...})` 的 `thing@program`；已归档旧 Agent 降级为普通可恢复事实，不在备份域激活权限。
- **内容守恒**：迁移不得丢失名称、Situation、层级、关系、历史归档身份或可恢复坐标。
- **证据时效**：OpenSpec 的历史 0/12 不覆盖上述已部署迁移事实；legacy 拒绝／迁移测试仍保留。当前公共 Help、生产 Agent 解析和最终候选1727/1727包含的源派生授权回归共同支持当前状态，不把旧勾选再翻译成待办。

## 3. 授权模型

### 3.1 标签与函数

- **管辖与钥匙**：连续 `^` 表示管辖等级；普通业务标签按已声明的锁参与精确钥匙匹配，但不扩大窗口或函数作用域。ESG规格§3的“总控”业务锁与当前Help遵循同一规则，不把两种作用混成只有 `^` 可匹配锁。
- **函数作用域**：`graph`、`form`、`program`、`work-order` 等声明限制 Agent 可执行的动作类别；持有路径钥匙不等于持有全部函数。
- **双重成立**：一次操作同时满足实际 slot 路径、目标锁标签和所需函数作用域才获准。
- **最小授权**：未声明、歧义、缓存缺失或目标路径变化时不得自动扩大权限。

### 3.2 统一裁定路径

- **同一规则**：Explore、Transform、Program 使用与 jump 调用同一授权裁定器，不维护入口专属白名单。
- **实际后代**：已登记 Agent 修改自身真实 slot 后代的 Situation/strut/Transform，不得误判为“登记自身”；同级、上级和越界目标仍拒绝。
- **Shortcut 边界**：Shortcut 仅用于定位，权限按目标的真实 slot 路径重新裁定。
- **错误可解释**：拒绝回执指出缺失的路径、标签或函数，不把不同原因折叠成通用 `WINDOW_ACCESS_DENIED`。

### 3.3 派生索引与回退

- **缓存性质**：权限索引、路径标签缓存、Agent registry 和反向索引都是带来源 revision 的派生物。
- **命中要求**：只有缓存 revision 与候选世界一致且信息完整时才能快速裁定。
- **安全回退**：缓存缺失、陈旧或诊断不一致时，从当前世界的 Agent/Program/Graph 事实局部重建后裁定。
- **禁止权威侧车**：lock/window snapshot/agent registration 侧车可以记录诊断或加速信息，但冷启动不能依赖其赋权。

## 4. 窗口与跳转

### 4.1 窗口边界

- **明确起点**：每个请求携带明确 Agent 身份和当前世界 revision；不把上个 Session 的默认 Agent 静默继承到新请求。
- **固定窗口**：Agent 的可见/可写窗口由当前世界中的注册事实、路径和锁计算，在单个裁定期间保持稳定。
- **变更重算**：slot、标签、注册或 Program 变化提交后，后续请求按新 revision 重算，不复用旧授权结论。
- **失败不漂移**：解析或授权失败时，当前窗口不得悄然跳到邻近同名节点。

### 4.2 受控 Jump 与自锁

- **显式跳转**：jump 必须给出目标并通过与 Explore/Transform 相同的路径、标签和函数裁定。
- **跨请求守卫**：需要跨冷启动保留的跳转边界应表达为可由 Program/Graph 重建的事实或规则，不能只写运行侧车。
- **自锁闭环**：获准跳转后的自锁与窗口变更进入同一事务回执；提交失败时窗口和锁都不变。
- **越界拒绝**：跨域、上行或不满足目标锁的 jump 返回稳定拒绝，不尝试宽松搜索。

### 4.3 上级 Agent 重配置

- **真实边界**：上级 Agent 只能在自身实际 slot 管辖域和声明函数内重配置后代 Agent/Program。
- **对象分类**：修改后代普通 Situation、strut 或 Program 正文属于目标 Transform；只有变更 `agent({...})` 注册事实才进入 Agent 登记合同。
- **原子更新**：注册事实、锁、窗口和派生索引由同一世界事务推进，不能先改侧车再补世界。
- **冷启动证明**：重配置成功必须经冷启动重建后仍保持同样授权结果。

### 4.4 子树迁移

- **按发起窗口裁定**：`Transform mov` 只按发起 Agent 对所选子树根的实际 slot 窗口与函数权限裁定；上级 Agent 可移动其窗口内后代，下级 Agent 不得向上、同级或跨域移动。
- **移动不是逐项重配置**：后代 Agent/Program 随父子树改变绝对路径，不等同于逐个修改其声明；只有声明内容发生非路径迁移变化时，才进入 Agent 重配置合同。
- **引用与身份守恒**：移动保持 Thing 身份、层级、正文、strut、锁和历史事实；由内核统一重写指向原路径的关系、Shortcut 与 Program 路径字面量。
- **派生状态重建**：提交前验证迁移后的 Program 声明，提交后按候选世界重建 Agent、lock、trigger、changed 等派生索引；后代引用路径重写不作为额外业务事件，所选根的真实 Transform 仍按既有订阅合同触发后续运行，不能一并停用 Trigger／Strut／阶段接棒。
- **路径边界**：只改写真正的精确或后代路径字面量，不改写注释、正文或仅共享字符串前缀的内容。
- **整体可逆归档（2026-09-05用户确认）**：合法上级对所选子树根发出纯`.dsc.`，整棵树进入唯一默认备份仓，内部结构并未被逐项编辑。不能为这次整体迁移再向每个后代申请slot编辑权，或用后代槽模的结构锁否定上级的整体操作。根的实际权限与锁、封装结构保护、引用完整性、备份停用和可逆恢复仍各自成立；规则适用于所有合法上级，不按manage等名称授予特例。直接编辑封装结构或混合编辑不得借归档获得旁路。

## 5. 创世与迁移

### 5.1 旧格式迁移

- **盘点分类**：按当前世界事实区分活跃注册、归档注册、非法/歧义声明和普通同名 Thing。
- **迁移顺序**：先生成可恢复备份和预期映射，再在授权维护事务中升级活跃项、降级归档项、重建索引。
- **失败回滚**：任一声明无法无损转换时停止整批提交并输出精确对象；不得边迁边让新旧格式同时长期生效。
- **完成条件**：公共 Help、解析器、CLI、冷启动和测试均只承认新格式，仓库中残留 legacy 字样仅存在于迁移/拒绝用例和历史材料。

### 5.2 零 Agent 创世

- **保留问题（低优先排队）**：#14 零Agent创世仍是未完成的独立产品能力；当前世界已有合法Agent，用户于2026-09-03明确不着急。依当前唯一总账与持续完成授权，排在A模式收束后单独设计／实施，不抢占当前生产故障，也不视为取消。
- **当前边界**：在专门设计获批前，不引入日常维护旁路、万能密钥或隐式初始 Agent。
- **未来结果**：需要形成“零 Agent 世界 → 受控女娲引导 → 首个合法 Agent → 旁路永久关闭”的一次性、可审计、可恢复闭环。
- **独立规格**：该能力会改变信任根，应在后续单独执行 brainstorming → spec → plan，而不塞入旧格式退役实施。

## 6. 错误与验收

### 6.1 错误合同

- **格式错误**：区分退役格式、声明缺失、声明重复、非法字面量和注册冲突。
- **授权错误**：区分路径越界、标签不匹配、函数缺失、窗口过期和目标歧义。
- **缓存异常**：先安全回退世界事实；若事实本身不一致则拒绝，并给出来源 revision 与诊断。
- **事务失败**：注册、跳转、自锁或重配置失败时，world、revision、窗口和索引均不得部分前进。

### 6.2 必要验收场景

- **格式矩阵**：合法 `thing@program` Agent、所有含 `@agent` 的旧 Key、零/多 `agent()`、动态声明、归档 Agent 和普通 Thing 全部有正反例。
- **权限矩阵**：后代允许、同级/上级/越界拒绝，业务标签不赋权，缺少函数拒绝，Explore/Transform/jump 结论一致。
- **迁移权限矩阵**：上级移动含下级 Agent Program 的后代子树成功，下级移动祖先失败；迁移后冷启动权限等价、旧路径索引消失且业务 Program 不被误触发。
- **缓存矩阵**：命中、缺失、陈旧、损坏与冷启动均得出相同授权结果，不因侧车存在与否改变权限。
- **迁移矩阵**：活跃升级、归档降级、失败全回滚、内容字节守恒以及旧格式永久拒绝。
- **真实 CLI**：新 Session 显式选择 Agent 后，查询、Transform、Program 与 jump 的回执可解释且交互不中断。

### 6.3 追溯关系

- **实现轨迹**：PR #15、#32、#58；它们提供局部实现线索，不覆盖当前 legacy 格式差距。
- **跨域依赖**：Program/slot 语义见世界规格；修订、缓存和事务见运行规格；跨任务真实使用见验收规格。
