# Superpowers 最小化检查点

本文件把 Ponytail 的有效部分收束为 Superpowers 的从属检查尺。Superpowers 仍是 Atom 唯一开发框架；本检查不注册独立流程、不建立第二套规格或账本，也不常态注入 Session。

## 权限顺序

`用户定论 → Atom 权威规格 → Superpowers 阶段与硬门禁 → 最小化检查 → Superpowers 验证`

出现冲突时，下级规则自动失效。最小化检查不得删减用户明确需求、数据守恒、鉴权、安全、可恢复迁移、错误处理、持久化上下文、TDD、验收或验证证据。

## 检查点 A：设计获批后、实施计划定稿前

只在批准的需求和架构内依次检查，命中首个可靠方案即停止扩张：

1. 是否根本无需新增实现；
2. 仓库是否已有可复用实现；
3. 标准库是否已覆盖；
4. 运行平台原生能力是否已覆盖；
5. 已安装依赖是否已覆盖；
6. 是否能以更少文件和更短作用链完成；
7. 否则实现满足规格的最小正确代码。

检查结果写入当前 Superpowers plan 的任务或约束，不另建 Ponytail plan。

## 检查点 B：提交前

对当前差异做一次复杂度审查，仅检查：重复实现、无使用者抽象、无必要依赖、死配置、远期脚手架和能够安全删除的中间层。任何采纳项必须重新运行当前任务的最小受影响测试；完成声明仍必须通过 `verification-before-completion`。

## 禁止接入方式

- 不安装或启用 Ponytail 常态 Hook、持久模式或根级 `AGENTS.md`。
- 不以“一个检查就够”为由降低 Superpowers TDD。
- 不因追求行数少而绕过事务、备份、回滚、revision 复验或失败原子性。
- 不允许最小化检查重新质疑已经批准且仍有效的产品需求。
