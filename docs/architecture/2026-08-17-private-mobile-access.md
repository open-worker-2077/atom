# Atom 私人手机接入架构

## 目标

在不公开 4784、不复制 Atom 世界、不引入离线多主写入的前提下，让一部已批准的安卓手机通过私人网络操作当前电脑上的同一 Atom。

## 系统本体

| 本体 | 权威事实 | 责任边界 |
|---|---|---|
| Atom 4784 | 世界事实、关系、Program、提交版本 | 继续只监听 `127.0.0.1:4784`，不感知手机平台 |
| 私人身份网关 | 获准的 Tailscale 登录身份或设备地址、远程会话准入 | 主入口验证 Serve 身份；直连入口只接受显式批准的 Tailscale 设备地址，再转发到 4784 |
| Tailscale Serve | 加密私网传输与设备级访问范围 | 只代理本机网关，不直接代理 4784；不得使用 Funnel |
| Web 交互层 | 手机和电脑的显示、触控与输入适配 | 只产生既有 Atom 交互意图，不拥有或缓存第二份世界事实 |
| 私人备份 | 已提交世界的恢复版本 | 保持现有私有备份边界，不进入公开 `atom` 仓库 |

数据主线只有一条：

`安卓浏览器 →〔HTTPS Serve 主入口｜Tailnet IP 直连入口〕→ 私人身份网关 → 127.0.0.1:4784 → Atom 事务提交 → 同步回显与私人备份`

## 系统定律

- 一个世界只有 4784 一个权威所有者；手机没有独立 `atom.json`。
- 一个编辑意图只经过既有 Atom 工作区提交边界；网关不解释业务语义。
- 远程入口默认拒绝：Serve 主入口缺少身份或身份不匹配时拒绝；直连入口来源不是获准手机的 Tailscale 地址时拒绝。
- 4784、私人网关和 Tailscale Serve 使用不同边界；误启 Funnel 时因缺少身份头而被网关拒绝。
- 第一阶段不提供离线编辑、云盘 JSON 同步或后台合并。
- 电脑本地入口不经过私人网关，远程接入故障不得影响 `127.0.0.1:4784`。

## 方案取舍

采用“双入口、同一身份网关、同一事实源”。HTTPS Serve 是主入口；Android 的 MagicDNS 链异常时，使用只绑定电脑 Tailscale IPv4、只接受获准手机 Tailscale IPv4 的 HTTP 直连入口。HTTP 仅承载于 Tailscale 的加密私网，不监听局域网或公网。两条入口都只转入同一个 4784，不产生第二份事实。

不采用公网端口、公开网站密码、云盘同步 JSON、首期原生安卓 App 或自建 VPN 控制面；这些方案会分别增加攻击面、认证维护、多主冲突或长期运维负担。

## 运行与失败

- 主网关监听 `127.0.0.1:4785`；直连网关只监听电脑的 Tailscale IPv4；4784仍保持原样。
- 手机断网、Tailscale断开或电脑休眠时，远程页面明确不可用，不排队保存未知状态。
- 同时操作仍由 4784 的既有提交队列和版本冲突规则排序；网关只做流式转发。
- 安装程序在发现已有 Tailscale Serve 配置时停止，避免覆盖其他本机服务。
- 停用只撤销本方案创建的 Serve 入口与计划任务，不重置整个 Tailscale 配置。

## 迁移与回滚

1. 先保存当前代码与私人数据恢复点。
2. 使用测试世界验证网关拒绝、身份允许、HTTP流式响应和SSE通知。
3. 安装 Tailscale，登录同一私人网络；启用设备审批和最小访问范围。
4. 先验证手机读取，再验证测试节点写入、电脑同步和刷新后持久化。
5. 最后启用登录时自动启动；任一验收失败即关闭 Serve 并移除网关任务，4784本机使用不变。

## 验收矩阵

| 要求 | 证据 |
|---|---|
| 无公网暴露 | 4784与4785均只监听回环地址；直连入口只监听 Tailscale IPv4；Funnel状态为空 |
| 身份最小化 | 主入口仅批准登录可访问；直连入口仅批准手机 Tailscale 地址可访问 |
| 单一事实源 | 手机写入由4784返回提交版本；不存在手机世界文件 |
| 多端一致 | 手机提交后电脑页面收到同一版本通知，刷新不回退 |
| 移动可用 | 安卓窄屏可选择节点、切换ASDF、展收、增改关系并确认/取消 |
| 可恢复 | 停用入口后本机4784正常；私人备份恢复门禁保持通过 |
