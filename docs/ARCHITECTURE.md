# 系统架构

## 系统目的

`graph-4d` 是三维视觉交互范式与本地优先知识库的试点。它用可缩放、可环绕、可递归进入的多球域承载节点和关系，验证传统表格／卡片界面能否被空间节点网络替代。

系统严格区分两类职责：

- **视觉交互层**：呈现空间、处理命中、视角旅行、节点展收、球镜和视觉意图。
- **数据脚本层**：解释业务动作、计算业务规则、审批、权限和外部数据流转。

知识库试点只提供通用节点、关系、详情和附件的本地存储，不把这些通用能力解释为任何具体业务流程。

## 组件

### 页面与视觉外壳

- `index.html`：语义结构、Canvas 和最小工具入口。
- `tokens.css`：深空视觉令牌。
- `spatial.css`：全屏空间场、HUD、搜索与编辑表面。

### 输入与空间语法

- `input-config.js`：鼠标、键盘等物理输入到视觉意图的可配置映射。
- `spatial-view-grammar.js`：语义尺度、交互阶段、Focus+Context、视角历史和可广播元数据边界。
- `spatial-entity-registry.js`：视觉实体、能力与渲染预算的白名单注册表。

输入映射不能直接实现业务功能。视觉语法只接受有限的视觉元数据，避免任意业务对象穿透到引擎。

### 三维视觉引擎

- `spatial-engine.js`：相机、投影、命中、环绕、缩放、递归球域、域径图与 Canvas 绘制。
- `spatial-visual-model.js`：关系投影、入口路由、视觉快照恢复和确定性张力排版等纯模型逻辑。

引擎通过 `spatial-visual-intent` 广播“发生了什么视觉意图”，但不决定外部脚本应如何处理业务数据。

### 知识工作区

- `spatial-workspace-model.js`：通用节点、关系、跨域落脚、历史别名、编辑事务和知识快照。
- `spatial-browser-bridge.js`：页面与浏览器本地存储或本地 HTTP 服务之间的同步桥。
- `cli/lib/store.mjs`：JSON 知识文件的规范化、查询与原子写入。
- `cli/lib/server.mjs`：静态页面、本地状态 API 与 CLI 共用的存储入口。
- `cli/spatial.mjs`：全局 `spatial` 命令行界面。

知识存储桥可以保存通用 Graph 数据，但不反向控制相机、球域旅行或视觉语义。

## 依赖方向

依赖保持单向：

1. 页面加载输入配置、视觉模型、空间语法、工作区模型和引擎。
2. 引擎读取模型并产生视觉输出与有限视觉意图。
3. 工作区模型维护通用知识快照，不调用 Canvas 绘制。
4. 浏览器桥只通过公开的 `window.spatialLab` 接口导入、导出知识与视图。
5. 本地服务和 CLI 共用存储层，但不引用浏览器引擎。
6. 外部业务脚本可以订阅视觉意图，视觉引擎不能依赖外部业务脚本。

## 持久化模式

### 文件入口

直接打开 `index.html` 时，浏览器使用本地存储保存知识快照。该模式不写入仓库文件。

### 本地服务入口

运行 `spatial serve` 后，页面、CLI 和 HTTP API 共享本机 `data/knowledge.json`。该文件属于运行数据，未纳入 Git 版本控制。

## 不变量

- 所有载体球都可以进入；空球表示尚无子内容，不表示不可扩展终点。
- 球镜展示与子域拓扑互相独立。
- 同层关系、父子关系和跨域关系使用不同的视觉提示。
- 逻辑递归可持续深入，但同屏实例、缓存、预取和历史均有上限。
- 排版是确定性约束场，不保存持续物理速度或业务状态。
- 本地知识数据不能进入源码提交或测试夹具。

## 验证

`npm.cmd test` 运行全部模型、交互、渲染契约、持久化、CLI、服务端与仓库治理测试。视觉或交互修改还必须进行真实浏览器渲染和输入路径验收。
