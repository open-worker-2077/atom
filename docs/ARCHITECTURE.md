# Atom 系统架构

## 定位

Atom 是一个可执行的高维事实世界，统一承载事实、关系、Program、Agent 与空间交互。Graph 是结构投影，Web 是空间交互入口；二者都不能成为与 `atom.json` 竞争的事实源。

当前定位已经在世界事实、统一运行脊柱、Program、Agent、Graph/Spatial 投影、事务、恢复和私密备份上形成可执行基础。尚未达标的主干是浏览器交互稳定性：编辑、权威回显、场景重建和视图保持之间缺少真实用户路径门禁，所以局部功能可能在后续改动中再次失效。

完整、可检查的能力与关系以 [atom-capability-graph.json](architecture/atom-capability-graph.json) 为准。该 JSON 同时记录能力所有者、完成状态、系统不变量、完整用户路径和验收缺口；本页只保留人工入口，不复制第二套架构事实。

## 运行主干

```text
人 / Agent / Program
        ↓ 明确意图
CLI / HTTP / Web 适配器
        ↓ 同一交互生命周期
世界查询 → Program 有界运行 → 原子提交
        ↓ 已提交世界修订
Graph 投影 → Spatial 投影
        ↓ 权威回显 + 独立视图事实
场景呈现与下一次交互
```

## 唯一所有权

| 事实 | 唯一所有者 | 禁止事项 |
|---|---|---|
| Atom 身份、内容、层级、关系、Program 源码、Agent 注册 | 世界内核 | Graph、Web 或缓存反写成为第二事实源 |
| 修订、提交顺序、事务历史、Program 运行结果 | 运行脊柱 | 绕过事务端口直接写世界 |
| Graph 与 Spatial 读模型 | 投影系统 | 接收业务写入或掩盖来源修订 |
| 相机、焦点、选择集、展开状态、视图模式和布局覆盖 | 空间体验 | 数据编辑、投影刷新或场景重建擅自改动视图 |
| 备份、恢复和健康证据 | 运行保障 | 备份成为在线事实源或进入公开仓库 |
| 能力图、验收映射和回归门禁 | 演进治理 | 仅以测试总数或源码文字匹配宣称功能完成 |

## 当前优先级

最高优先级不是继续修补单个按钮，而是闭合“Web 编辑并保持视角”路径：

```text
空间输入 → 工作区编辑 → 统一运行时 → 世界提交
→ Spatial 投影 → 权威回显 → 场景呈现
```

这条路径必须共同遵守三条规则：

1. 每个操作精确触发一次提交，多步和多端操作按修订排队。
2. 编辑只改变世界事实；没有明确视图意图时，相机、焦点、选择、展开状态和模式保持不变。
3. 只有真实浏览器完成输入、保存、回显和最终画面验收，才可标记为完成；模型测试或源码匹配只能作为辅助证据。

## 验证入口

- `npm run test:architecture`：系统边界、事实所有权和依赖方向。
- `npm run test:system`：事务、并发、Program、恢复、投影与容量。
- `npm test`：全部模型、适配器、服务和回归测试。
- `tests/atom-capability-graph.test.mjs`：能力图连通性、唯一所有权、用户路径和证据完整性。

真实浏览器交互门禁仍是能力图中明确登记的缺口；在补齐前，不再把 Web 交互稳定性描述为“已完成”。
