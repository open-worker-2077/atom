# Spatial KB CLI 试点设计

## 边界

- 3D 引擎只负责场域、视角、节点和关系的视觉交互。
- 知识数据由独立 JSON 存储层负责；页面和 CLI 都通过同一组稳定键读写。
- CLI 不模拟鼠标键盘，也不读取 Canvas 像素。

## 交付形态

1. 全局命令 `spatial`：离线也能对知识库执行节点、关系、搜索和查询。
2. `spatial serve`：在 `127.0.0.1` 启动本地页面和数据桥，使页面与 CLI 共用一份 JSON。
3. 页面桥：只同步已提交的工作区快照与当前视图；桥不可用时，页面仍可独立运行。
4. 稳定身份：节点使用 `<域径>::<节点 ID>`，关系使用排序后的两个端点生成 ID。

## 跨域落脚修复

- 域切换分成“旧域接近”和“新域稳定”两个阶段。
- 新域已经出现时，Ctrl 编辑手势立即可用，不再被剩余镜头缓动静默丢弃。
- 旧域尚未切走时仍保持锁定，避免把落脚误记在旧域。
- 文件入口的本地脚本带构建版本，页面显示构建号，避免误用旧缓存。

## 数据文件

默认文件为 `data/knowledge.json`，包含：

- `schemaVersion`、`revision`、更新时间；
- 用户新增节点；
- 对内置节点的修改补丁与删除标记；
- 同域和跨域关系；
- 节点历史域径别名，用于解析落脚后仍未改写的旧关系端点；
- 最近一次页面视图投影。

写入采用同目录临时文件后原子替换，避免中途退出留下半份 JSON。

## 首批命令

- `spatial init|doctor|serve`
- `spatial field get`、`spatial view get`
- `spatial node list|get|create|update|land|delete`
- `spatial edge list|create|delete`
- `spatial search`

所有查询默认输出便于人读的 JSON；`--json` 提供稳定的单行机器输出。

`node land` 只更新节点当前域径与空间位置，旧键进入别名集合，既有关系记录保持原端点，供页面显示跨域长尾并由人工决定是否删除。
