# ADR 0005：Boss 隔离 JSON 与只生长历史

## 状态

开发中。

## 决策

- `bossId` 指向所属顶层 Boss，并决定节点存入哪个独立 JSON。
- `leaderId` 指向直属上级；顶层 Boss 的 `leaderId` 固定为 `null`。
- `catalog.json` 只登记 Boss、文件位置和目录状态，不承载知识正文。
- 当前交互数据位于 `bosses/<bossId>.json`。
- 安全历史位于 `history/<bossId>.history.json`。
- 每次变更向历史树新增一个分支，完整保留变更前和变更后的知识快照。
- 非顶层节点必须具有 `leaderId`；Leader 调整后，其整棵下级分支随之重算域径。
- 循环 Leader、跨 Boss 污染、直接伪造域径和重复 `nodeId` 在写入前拒绝。
- 有下级的 Leader 默认拒绝删除；只有界面明确确认后传入递归删除意图才删除整枝。
- Boss 根节点不接受普通节点删除命令。
- 数据撤销与重做使用同一只生长历史：撤销和重做本身也追加审计枝，不裁剪旧枝。
- 新的多 Boss 界面应将 `Z` 路由为当前 Boss 数据撤销、`X` 路由为数据重做；没有数据历史时才允许回退到原视图历史。
- 历史不可解析、缺失或 Boss 不匹配时，交互写入必须在修改当前 JSON 之前失败。
- 所有 JSON 先写入可解析的临时文件，再原子替换正式文件。
- 同一 Boss 的跨进程写入使用独占锁串行化，避免页面与 Agent 同时写入时丢失更新。
- 现有 `data/knowledge.json` 不自动迁移、不覆盖；迁移必须是显式的独立操作。

## Windows 与 GitHub 备份

`scripts/backup-boss-json.ps1` 将全部 JSON 复制到独立的私有 Git 仓库，再提交并推送。
备份脚本只复制或更新文件，绝不因源目录缺失文件而删除备份端文件。
`scripts/install-boss-backup-task.ps1` 可注册开机触发和周期触发任务；安装任务属于系统变更，需人工明确执行。

## 当前边界

这一阶段已经接入隔离存储、安全历史、CLI、浏览器聚合编辑、有下级 Leader 的删除确认，
以及当前 Boss 的 `Z` 数据撤销 / `X` 数据重做。跨 Boss 移动、跨 Boss 关系和旧单文件迁移
仍需在后续阶段完成事务设计后接入，避免把多文件写入伪装成一次原子操作。
