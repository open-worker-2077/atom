## Why

Atom 已能复制子树、运行 Program 并按窗口结果锁定节点，但尚不能把使用方在世界中研磨出的复合槽正式封装为“槽体”，也不能从一个显式空槽例原子打印具名业务槽例、让槽模结构持续映照空槽例与既有槽例。使用方因此仍需手工递归建槽、重接推线和重复维护 Program，无法稳定承载字段流、表单流、业务流与场景流。

## What Changes

- 新增公共内核函数 `slot_body()`，以统一动作管理“槽体／槽模／槽例／空槽例／业务槽例”的显式 Graph 结构，不增加新的 Atom 持久化轴或可执行类型。
- 支持将既有完整槽图封装为槽体：槽模保持指它性定义与共享 Program，空槽例作为可试跑、可复制的实际 Graph 子树，业务槽例与空槽例共同归入槽例。
- 支持从空槽例一次性打印具名业务槽例；打印复用权威子树复制语义，保留全部后代与料、重定向副本内部推线，并在重名或结构不完整时整次拒绝。
- 支持槽模结构映照：新增、重命名、移动、类型／说明和推线变化同步作用于空槽例及所属业务槽例，既有料字符保持原样；共享 Program 只保存在槽模并由槽例按稳定角色引用。
- 将结构映照限定在当前槽体局部，只沿显式槽模角色和槽例归属计算；不扫描或重算整个 Atom 世界。
- 扩展现有窗口识别锁的通用条件表达：节点锁按窗口类型、目标状态和动作分别判断，不固化具体窗口 ID 或识别名称；具体窗口的守窗、跳窗、关窗和滚动绑定仍由总控 Agent 依据业务调用，不由内核写死。
- 在 Program 函数注册表、CLI Help 和运行时文档中公开准确 JSON 契约、结果、错误、兼容边界与回读要求。
- 保持现有 `.cpy.`、`instantiate()`、`template_catalog()`、`form()`、`work_order()`、Program trigger 和 window-aware lock 行为兼容。

## Capabilities

### New Capabilities

- `slot-body-runtime`: 显式槽体结构、槽模封装、空槽例打印、共享 Program、局部结构映照、类型条件锁复用和验收回执。
- `window-type-lock-conditions`: 在兼容具体窗口名单的同时，新增按窗口类型、目标状态与交互动作分别求值的锁条件。

### Modified Capabilities

无。现有具体窗口名单、Program 模板和 Graph Transform 契约作为兼容基线保留；新增条件不改变旧调用的结果。

## Impact

- Program Python 安全命名空间与 Node Program 运行时效果提交。
- Graph 子树复制／具名副本规划及局部结构映照逻辑。
- Program 函数注册表、CLI Help 与运行时说明。
- 槽体单元测试、Program 集成测试、CLI／服务端真实端到端测试和 Atom `test` 范围验收。
- 4784 服务在交付时需要加载新运行时，并以 Help、正向打印、结构映照、重复名拒绝和非允许窗口拒绝证明实际生效。
