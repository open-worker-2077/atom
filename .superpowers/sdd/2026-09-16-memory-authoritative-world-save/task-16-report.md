## Ownership result and limits

The memory port now privately claims a final plain-JSON candidate only after the engine's existing precommit validation. A claim deeply seals and computes its canonical revision; the coordinator retains revision/conflict/receipt checks, and only that claimed identity skips the port's acceptance clone. Unclaimed inputs still receive an isolated clone. The persistence facade's internal owned read stays under recovery, serialized inspection, and manifest validation; the public read still clones. Context preparation validates revision, manifest provenance, and Graph projection for both routes, but only the internal sealed route reuses facts. Public caller facts are cloned then sealed before repeated revision checks. Accessor, exotic mutable, proxy, sparse, cycle, shallow-frozen, and forged-revision inputs cannot provide ownership proof.

By source-path inspection and identity assertions, the normal claimed memory path removes the former full-facts clone at acceptance, the internal postcommit/read snapshot clone, and the committed-context preparation clone; hash reuse follows the exact sealed fact identity. This is a structural reduction, not a measured full-copy latency result. The existing flat SHA-256 revision still needs at least one whole-world serialization/hash per changed candidate; some earlier change-detection paths may hash before final sealing. Compatibility scanning, Graph validation, and backup-boundary key parsing remain. `inheritPreparedAccessWorld` was intentionally not moved: activating it now would introduce another full-archive `walkAtoms` on the waiting chain. Active/archive COW and index work remains the separately planned boundary.
